Convolution The fundamental operation behind almost everything

💡 Real Life Analogy
Imagine you're stamping a rubber stamp across a piece of paper. The stamp is the kernel, the paper is the image. Every position you stamp, you combine the stamp's pattern with what's underneath. That combined result becomes the new image. Convolution is just doing this systematically at every pixel.

Convolution is the core operation. You slide a small matrix called a kernel (or filter) over every pixel of the image. At each position, you multiply the kernel values with the pixel values underneath, sum them all up, and that becomes the new pixel value.

// Formula
(I ∗ K)[x, y] = Σᵢ Σⱼ I[x+i, y+j] · K[i, j]
I = input image  |  K = kernel (filter)  |  (x,y) = pixel position
The kernel slides over every pixel. Σ sums all products of overlapping values.

Think of it as a weighted average of neighbours. Depending on what weights you put in the kernel, you get blur, sharpening, edge detection — all using the same math.

convolution_basics.py python 
import cv2
import numpy as np

# Load image
img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# Define a custom kernel (identity = no change)
identity_kernel = np.array([
    [0, 0, 0],
    [0, 1, 0],   # Only centre pixel contributes
    [0, 0, 0]
], dtype=np.float32)

# Apply convolution using filter2D
# -1 = output depth same as input
result = cv2.filter2D(img, -1, identity_kernel)

# Sharpening kernel (enhances centre, subtracts neighbours)
sharpen = np.array([
    [ 0, -1,  0],
    [-1,  5, -1],
    [ 0, -1,  0]
], dtype=np.float32)

sharpened = cv2.filter2D(img, -1, sharpen)

cv2.imshow('Original', img)
cv2.imshow('Sharpened', sharpened)
cv2.waitKey(0)

Gaussian Blur Weighted blur that mimics how cameras go out-of-focus

💡 Real Life Analogy
Think of looking through frosted glass. Things directly in front are somewhat visible, things at the edges blur away. The Gaussian function creates exactly this bell-curve weighting — the farther a pixel is from the centre, the less it contributes to the blur. Unlike a box blur (average all neighbours equally), Gaussian feels "natural" because our eyes work the same way.

The Gaussian kernel is generated from the normal distribution formula. A σ (sigma) controls the spread — higher σ = more blur. Every pixel becomes a weighted average of its neighborhood, where weights follow a bell curve.

// 2D Gaussian Formula
G(x, y) = (1 / 2πσ²) · e^(-(x² + y²) / 2σ²)
x, y = distance from kernel centre  |  σ = standard deviation (controls blur strength)
e ≈ 2.718 (Euler's number). The exponent creates the bell-curve falloff.
The result is then normalised so all weights sum to 1 (no brightness change).

Sobel Operator & Image Gradients Detecting where brightness changes rapidly

💡 Real Life Analogy
Imagine driving along a road. When the road is flat, your car doesn't tilt — no gradient. At a hill, your car tilts — large gradient. At a cliff edge, maximum tilt. The Sobel operator finds these "brightness cliffs" in an image — places where pixel values jump suddenly. Those jumps are edges. It computes the derivative (rate of change) in X and Y directions separately.

A gradient measures how fast a function changes. In an image, we compute it in X (horizontal) and Y (vertical) directions. Sobel combines a smoothing step (Gaussian-like) with a derivative — making it robust to noise.

// Sobel Gradient Formulas
Gₓ = Kₓ ∗ I    (horizontal gradient)
Gᵧ = Kᵧ ∗ I    (vertical gradient)

Magnitude: |G| = √(Gₓ² + Gᵧ²)
Direction: θ = arctan(Gᵧ / Gₓ)
|G| tells you HOW STRONG the edge is. θ tells you WHICH DIRECTION the edge runs.
A vertical wall has θ ≈ 0°. A horizontal horizon has θ ≈ 90°.

sobel_gradient.py python 
import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# Sobel: ddepth=-1 means output same depth as input
# dx=1, dy=0 → only horizontal gradient (vertical edges)
# ksize=3  → 3x3 kernel (or 5, 7 for stronger)
sobelX = cv2.Sobel(img, cv2.CV_64F, dx=1, dy=0, ksize=3)
sobelY = cv2.Sobel(img, cv2.CV_64F, dx=0, dy=1, ksize=3)

# Combine: gradient magnitude
magnitude = np.sqrt(sobelX**2 + sobelY**2)
magnitude = np.uint8(np.clip(magnitude, 0, 255))

# Gradient direction (in degrees)
direction = np.arctan2(sobelY, sobelX) * (180 / np.pi)

# Show absolute values (negatives become positives)
abs_sobelX = cv2.convertScaleAbs(sobelX)
abs_sobelY = cv2.convertScaleAbs(sobelY)

# Weighted combination
combined = cv2.addWeighted(abs_sobelX, 0.5, abs_sobelY, 0.5, 0)

# Scharr = improved Sobel (better rotation invariance)
scharrX = cv2.Scharr(img, cv2.CV_64F, dx=1, dy=0)

cv2.imshow('Sobel X', abs_sobelX)
cv2.imshow('Sobel Y', abs_sobelY)
cv2.imshow('Magnitude', magnitude)

Laplacian Operator Second derivative — finds edges in all directions at once

💡 Real Life Analogy
Where Sobel checks "is it going uphill?" (1st derivative), the Laplacian asks "is it going uphill and then immediately downhill?" — i.e. did we cross a peak? Think of sound: a drum hit has a sharp spike then returns to silence. The Laplacian detects these zero-crossings. It's like a "second opinion" — not just that things are changing, but that they just changed direction.

The Laplacian is the sum of second-order partial derivatives. It's isotropic — responds to edges in all directions equally. However, it's very sensitive to noise, so it's almost always applied after Gaussian blurring. This combined operation is called LoG (Laplacian of Gaussian).

// Laplacian Formula
∇²f = ∂²f/∂x² + ∂²f/∂y²
Discretised (approximated) as a kernel.
LoG: Apply Gaussian first to smooth noise, then Laplacian for edges.
∇²(G ∗ I) = (∇²G) ∗ I — this is why LoG = "Mexican hat" kernel

import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# Laplacian — always blur first to reduce noise!
blurred = cv2.GaussianBlur(img, (5, 5), 0)

# CV_64F = 64-bit float (captures negatives)
# ksize=1 → uses the 3x3 cross kernel shown above
laplacian = cv2.Laplacian(blurred, cv2.CV_64F, ksize=3)

# Convert back to uint8 for display
laplacian_abs = cv2.convertScaleAbs(laplacian)

# LoG approach manually:
# blur_img = GaussianBlur → then Laplacian
# This is mathematically equivalent to LoG kernel

# Sharpening using Laplacian:
# Subtract Laplacian from original image
sharpened = cv2.addWeighted(img, 1.0, laplacian_abs, -1.0, 0)

# Focus measure — variance of Laplacian
# High value = in-focus. Low value = blurry.
focus_measure = laplacian.var()
print(f"Focus score: {focus_measure:.2f}")
if focus_measure > 100:
    print("Image is in focus")
else:
    print("Image is blurry")

Canny Edge Detection The gold standard — a multi-stage intelligent pipeline

💡 Real Life Analogy
Imagine tracing the outline of objects in a photo. Canny does this in stages like a detective: (1) clean the scene — remove noise (Gaussian). (2) find clues — compute gradients (Sobel). (3) narrow it down — keep only the sharpest points along each edge (NMS). (4) verify with evidence — only keep edges connected to strong signals (hysteresis). The result: clean, thin, complete edges. No false positives.
STEP 01
Gaussian Smooth

Remove noise to prevent false edges

STEP 02
Sobel Gradient

Find magnitude & direction at each pixel

STEP 03
Non-Max Suppression

Thin edges to 1-pixel width

STEP 04
Double Threshold

Mark strong, weak & non-edge pixels

STEP 05
Hysteresis Tracking

Keep weak edges connected to strong ones

// Hysteresis Thresholding Logic
pixel value > T_high → strong edge (keep ✓)
T_low < value < T_high → weak edge (keep if connected to strong ✓)
pixel value < T_low → not an edge (discard ✗)
T_high : T_low ratio is usually 2:1 or 3:1
Typical: T_low = 50, T_high = 150
Non-Maximum Suppression: along gradient direction θ, if a pixel isn't the LOCAL MAXIMUM, set it to 0 — this thins edges to single pixels.
canny_edge.py python 
import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# Step 1: Pre-blur (Canny does its own blur,
#         but extra blur helps for noisy images)
blurred = cv2.GaussianBlur(img, (5, 5), 0)

# Canny(image, threshold1=low, threshold2=high)
# Rule of thumb: high = 2x or 3x low
edges = cv2.Canny(blurred, threshold1=50, threshold2=150)

# Auto-threshold trick: use median pixel value
v = np.median(img)
sigma = 0.33
lower = int(max(0,   (1.0 - sigma) * v))
upper = int(min(255, (1.0 + sigma) * v))
auto_edges = cv2.Canny(blurred, lower, upper)

# L2gradient=True uses √(Gx²+Gy²) instead of |Gx|+|Gy|
# More accurate but slower
precise = cv2.Canny(blurred, 50, 150, L2gradient=True)

# Dilate edges to make them thicker/visible
kernel = np.ones((2, 2), np.uint8)
thick_edges = cv2.dilate(edges, kernel, iterations=1)

# Overlay edges on original image (colored)
color_img = cv2.imread('image.jpg')
color_img[edges != 0] = [0, 255, 0]  # green edges

cv2.imshow('Canny Edges', edges)
cv2.imshow('Auto Canny', auto_edges)
cv2.waitKey(0)

Thresholding Converting grayscale to binary: black or white, nothing in between

💡 Real Life Analogy
Imagine a nightclub with a height requirement: anyone above 180cm gets in (white = 255), everyone else stays out (black = 0). Simple threshold works for uniform lighting. But Adaptive threshold is like having different entry requirements in different rooms of the club — it adapts to local conditions, like how your eyes adjust from a bright lobby to a dark dance floor.
// Threshold Formula
dst(x,y) = maxVal if src(x,y) > T
dst(x,y) = 0 otherwise
Otsu's method: automatically finds the OPTIMAL T by minimizing intra-class variance.
It looks at the histogram and finds the threshold that best separates two peaks.
Adaptive: T(x,y) = weighted_mean(neighbourhood) − C (local threshold per pixel)
thresholding.py python 
import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# Simple threshold: pixels > 127 → 255, else → 0
ret, binary = cv2.threshold(img, 127, 255, cv2.THRESH_BINARY)

# Inverse: pixels > 127 → 0, else → 255
ret, inv = cv2.threshold(img, 127, 255, cv2.THRESH_BINARY_INV)

# Truncate: pixels > 127 → 127 (cap the value)
ret, trunc = cv2.threshold(img, 127, 255, cv2.THRESH_TRUNC)

# Otsu's: automatically finds best threshold
# Returned ret is the auto-found threshold value
ret, otsu = cv2.threshold(img, 0, 255,
                           cv2.THRESH_BINARY + cv2.THRESH_OTSU)
print(f"Otsu threshold: {ret}")

# Adaptive: calculates threshold per local region
# blockSize=11: neighbourhood size (must be odd)
# C=2: subtract 2 from mean (fine-tune sensitivity)
adaptive_mean = cv2.adaptiveThreshold(
    img, 255,
    cv2.ADAPTIVE_THRESH_MEAN_C,
    cv2.THRESH_BINARY,
    blockSize=11, C=2
)

# Gaussian adaptive: better for images with gradients
adaptive_gauss = cv2.adaptiveThreshold(
    img, 255,
    cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
    cv2.THRESH_BINARY,
    blockSize=11, C=2
)

Morphological Operations Shape-based manipulation of binary images

💡 Real Life Analogy
Think of white shapes on a black background as blobs of dough, and the kernel as a cookie cutter. Erosion = shrink the dough (small blobs disappear, large ones get smaller). Dilation = expand the dough (fill gaps, connect nearby pieces). Opening = erode then dilate (remove tiny noise blobs but keep big shapes). Closing = dilate then erode (fill holes in shapes).
⬛

Erosion

A pixel is kept white ONLY if ALL pixels under the kernel are white. Shrinks shapes, removes small blobs, thins edges. Formula: dst = min over kernel neighbourhood

⬜

Dilation

A pixel becomes white if ANY pixel under the kernel is white. Grows shapes, fills small holes, thickens edges. Formula: dst = max over kernel neighbourhood

🔵

Opening (erode→dilate)

Removes small noise/speckles while preserving the size and shape of larger objects. Great for cleaning up binary masks after thresholding.

🟢

Closing (dilate→erode)

Fills small holes inside objects and closes small gaps between nearby shapes. Good for making solid masks from broken contours.

morphology.py python 
import cv2
import numpy as np

img = cv2.imread('binary_image.jpg', cv2.IMREAD_GRAYSCALE)
_, binary = cv2.threshold(img, 127, 255, cv2.THRESH_BINARY)

# Structuring element (kernel) — shapes matter!
rect_kernel  = cv2.getStructuringElement(cv2.MORPH_RECT,  (5,5))
cross_kernel = cv2.getStructuringElement(cv2.MORPH_CROSS, (5,5))
ellip_kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5,5))

kernel = rect_kernel

# Basic operations
eroded  = cv2.erode(binary, kernel, iterations=1)
dilated = cv2.dilate(binary, kernel, iterations=1)

# Compound operations via morphologyEx
opened  = cv2.morphologyEx(binary, cv2.MORPH_OPEN,    kernel)  # erode→dilate
closed  = cv2.morphologyEx(binary, cv2.MORPH_CLOSE,   kernel)  # dilate→erode
gradient= cv2.morphologyEx(binary, cv2.MORPH_GRADIENT, kernel)  # dilate−erode = edge
tophat  = cv2.morphologyEx(binary, cv2.MORPH_TOPHAT,   kernel)  # original−opened
blackhat= cv2.morphologyEx(binary, cv2.MORPH_BLACKHAT, kernel)  # closed−original

# Practical example: remove noise and fill gaps
# after Canny edge detection
edges = cv2.Canny(img, 50, 150)
clean_edges = cv2.morphologyEx(edges, cv2.MORPH_CLOSE,
                                np.ones((3,3), np.uint8))

Histogram Equalisation Spreading pixel intensity distribution for better contrast

💡 Real Life Analogy
Imagine a classroom where all students scored between 60–70 out of 100. The teacher "equalises" the grades by spreading them across 0–100. Histogram equalisation does the same: if all pixels are crammed into a narrow range (image looks grey and flat), it stretches them to span 0–255 fully. Now dark areas become darker and bright areas brighter — contrast improves dramatically.
// Equalisation Formula
H(v) = count of pixels with value v
CDF(v) = Σₖ₌₀ᵛ H(k) (cumulative distribution)

new_value = round( (CDF(v) - CDF_min) / (N - CDF_min) × (L-1) )
N = total pixels  |  L = 256 (number of levels)  |  CDF_min = smallest non-zero CDF value
CLAHE (Contrast Limited Adaptive Histogram Equalisation) applies this locally
to tiles of the image and clips the histogram to avoid noise amplification.
histogram_eq.py python 
import cv2
import numpy as np

img = cv2.imread('dark_image.jpg')
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# Basic global equalisation
eq_gray = cv2.equalizeHist(gray)

# CLAHE: adaptive, tile-based, much better result
# clipLimit: cap histogram before redistribution
# tileGridSize: size of each tile region
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
eq_clahe = clahe.apply(gray)

# For colour images: equalise only the V (brightness)
# channel in HSV, not all 3 channels
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
hsv[:,:,2] = clahe.apply(hsv[:,:,2])  # apply to Value channel
result = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)

# Plot histogram manually
hist = cv2.calcHist([gray], [0], None, [256], [0, 256])
print("Histogram shape:", hist.shape)  # (256, 1)

all_edge_methods.py — complete pipeline python 
import cv2
import numpy as np

def compare_edge_methods(image_path):
    img = cv2.imread(image_path, cv2.IMREAD_GRAYSCALE)
    blurred = cv2.GaussianBlur(img, (5, 5), 0)

    # --- Sobel ---
    sx = cv2.Sobel(blurred, cv2.CV_64F, 1, 0, ksize=3)
    sy = cv2.Sobel(blurred, cv2.CV_64F, 0, 1, ksize=3)
    sobel = cv2.convertScaleAbs(np.sqrt(sx**2 + sy**2))

    # --- Laplacian ---
    laplacian = cv2.convertScaleAbs(
        cv2.Laplacian(blurred, cv2.CV_64F))

    # --- Canny ---
    canny = cv2.Canny(blurred, 50, 150)

    # --- Prewitt (via filter2D) ---
    prewitt_x = cv2.filter2D(blurred, -1,
        np.array([[-1,0,1],[-1,0,1],[-1,0,1]], dtype=np.float32))
    prewitt_y = cv2.filter2D(blurred, -1,
        np.array([[-1,-1,-1],[0,0,0],[1,1,1]], dtype=np.float32))
    prewitt = cv2.convertScaleAbs(
        np.sqrt(prewitt_x.astype(float)**2 + prewitt_y.astype(float)**2))

    # Stack results in a grid
    row1 = np.hstack([img, sobel])
    row2 = np.hstack([laplacian, canny])
    grid = np.vstack([row1, row2])

    cv2.imshow('Edge methods: Original | Sobel | Laplacian | Canny', grid)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

compare_edge_methods('image.jpg')

Quick Decision Guide

For general edge detection → Canny. For gradient direction → Sobel. For focus detection → Laplacian.var(). For low-light images → CLAHE + Canny.

The Golden Pipeline

Grayscale → Gaussian Blur → Threshold / Canny → Morphological cleanup. This handles 90% of practical computer vision edge/shape tasks.

Kernel size = 2 × ceil(3σ) + 1. So σ=1 → size=7, σ=2 → size=13. OpenCV often lets you pass σ and it auto-computes the kernel size.

Colour Space Transformations

// Why RGB is not always the right way to represent colour

💡 Real Life Analogy
RGB is like describing a person by their exact bone structure — precise but fragile. Change the lighting and all three numbers change drastically, even though the person looks the same. HSV is like describing them as "tall, wearing a red jacket, standing in shadows" — hue (colour identity) stays the same even when brightness changes. This is why HSV is used for colour-based object tracking.

Different tasks need different colour spaces. RGB mixes colour and brightness. HSV/HSL separates them. LAB mimics human perception. YCrCb is used in video/compression (separates luma from chroma).

// RGB → HSV conversion
Let R,G,B ∈ [0,1] V = max(R,G,B) S = (V - min(R,G,B)) / V (if V ≠ 0) H = 60 × (G - B)/(V - min) if V = R H = 60 × (B - R)/(V - min) + 120 if V = G H = 60 × (R - G)/(V - min) + 240 if V = B H = H + 360 if H < 0
H = Hue [0°–360°] — the colour wheel angle
S = Saturation [0–1] — how "vivid" vs grey
V = Value [0–1] — brightness
OpenCV stores H/2 (0–180), S×255, V×255 in uint8
// RGB → CIE LAB (perceptually uniform)
Step 1: RGB → XYZ (via linear transform + gamma) Step 2: XYZ normalised by D65 white point (Xn,Yn,Zn) Step 3: f(t) = t^(1/3) if t > 0.008856 f(t) = 7.787t + 16/116 otherwise L* = 116·f(Y/Yn) - 16 (lightness, 0–100) a* = 500·(f(X/Xn) - f(Y/Yn)) (green↔red axis) b* = 200·(f(Y/Yn) - f(Z/Zn)) (blue↔yellow axis)
LAB: equal Euclidean distances = equal perceived colour differences.
Perceptual colour distance: ΔE = √(ΔL² + Δa² + Δb²)
Very useful for comparing colours the way humans see them.

02 · Frequency Domain

Fourier Transform

// Decomposing images into sine waves

💡 Real Life Analogy
A song is just air pressure over time. But you can view it as a spectrum in a music equaliser — seeing which frequencies are loud (bass, treble). The Fourier Transform does the same for images: it shows which spatial frequencies are present. Low frequencies = gradual brightness changes (backgrounds). High frequencies = sharp edges, fine texture, noise. You can then filter frequencies before converting back — like tweaking the EQ.
// 2D Discrete Fourier Transform (DFT)
F(u, v) = Σₓ Σᵧ f(x,y) · e^(-j2π(ux/M + vy/N)) Power Spectrum: |F(u,v)|² = Re(F)² + Im(F)² Inverse DFT (reconstruct image): f(x,y) = (1/MN) Σᵤ Σᵥ F(u,v) · e^(j2π(ux/M + vy/N))
u,v = frequency coordinates  |  x,y = spatial coordinates
M,N = image dimensions  |  j = √(-1) (imaginary unit)
Centre of spectrum = DC component (average brightness) = lowest freq
Corners = highest spatial frequencies (fine detail, noise)
🔇

Low-pass filter

Keep only low-frequency components (small circle in centre of spectrum). Result: blurred image. Removes noise and fine detail. Equivalent to Gaussian blur.

🔔

High-pass filter

Remove low frequencies, keep high. Result: edges and textures highlighted, background removed. Used for sharpening and texture analysis.

🎚️

Band-pass filter

Keep only a ring of frequencies. Useful for finding periodic patterns, removing specific noise (e.g. moire patterns from scanned images).

fourier_filtering.pypython
import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# ── Forward DFT ──────────────────────────────────
dft = np.fft.fft2(img)                  # complex 2D array
dft_shifted = np.fft.fftshift(dft)     # move DC to centre

# Visualise as log magnitude spectrum
magnitude = np.abs(dft_shifted)
log_spectrum = 20 * np.log10(magnitude + 1)
spectrum_vis = cv2.normalize(log_spectrum, None, 0, 255,
                               cv2.NORM_MINMAX, cv2.CV_8U)

# ── Low-pass filter (blur in frequency domain) ───
rows, cols = img.shape
crow, ccol = rows // 2, cols // 2
radius = 30  # pixels — larger = less blur

mask = np.zeros((rows, cols), np.uint8)
cv2.circle(mask, (ccol, crow), radius, 1, -1)  # circular window

# Apply mask → inverse DFT → reconstruct image
filtered_dft = dft_shifted * mask
idft_shifted  = np.fft.ifftshift(filtered_dft)
img_back = np.abs(np.fft.ifft2(idft_shifted))
img_back = np.uint8(np.clip(img_back, 0, 255))

# ── High-pass filter ──────────────────────────────
hp_mask = 1 - mask   # invert: keep edges not centre
hp_fft = dft_shifted * hp_mask
hp_back = np.abs(np.fft.ifft2(np.fft.ifftshift(hp_fft)))
hp_back = cv2.normalize(hp_back, None, 0, 255, cv2.NORM_MINMAX, cv2.CV_8U)

# OpenCV also has dft: slightly faster for large images
dft_cv = cv2.dft(np.float32(img), flags=cv2.DFT_COMPLEX_OUTPUT)
03 · Shape Detection

Hough Transform

// Detecting lines, circles, and arbitrary shapes by voting

💡 Real Life Analogy
You have many dots on a piece of paper and want to find which line passes through the most dots. Instead of testing every possible line, the Hough Transform inverts the problem: each dot votes for all possible lines it could be on. Lines that get the most votes probably exist. It's like an election — if many people independently "vote" for the same candidate, that candidate is real.
// Hough Line Transform — Normal form
ρ = x·cos(θ) + y·sin(θ) ρ = perpendicular distance from origin to line θ = angle of the perpendicular (0° to 180°) For each edge pixel (x,y): for each θ in [0°, 180°]: ρ = x·cos(θ) + y·sin(θ) accumulator[ρ][θ] += 1 ← VOTE! Peak in accumulator = detected line
(ρ,θ) = Hough parameter space (accumulator array)
Traditional (y=mx+b) fails for vertical lines (m=∞). Normal form avoids this.
Probabilistic Hough (HoughLinesP) is faster — samples random edge subsets.
// Hough Circle Transform
Circle: (x - a)² + (y - b)² = r² For each edge pixel (x,y) and each radius r: for each angle θ in [0°, 360°]: a = x - r·cos(θ) b = y - r·sin(θ) accumulator[a][b][r] += 1 Peak at (a,b,r) = circle centre at (a,b) with radius r
Computationally heavy (3D accumulator). OpenCV uses gradient-based method (faster).
param1 = Canny high threshold used internally
param2 = accumulator threshold (higher = fewer, more certain circles)
hough_detection.pypython
import cv2
import numpy as np

img   = cv2.imread('image.jpg')
gray  = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# threshold=100: minimum votes to be a line
# minLineLength=50: discard lines shorter than 50px

lines = cv2.HoughLinesP(edges,

    cv2.HOUGH_GRADIENT, dp=1, minDist=30,

Contours & Shape Descriptors

// Finding, measuring and classifying shapes mathematically

💡 Real Life Analogy
Imagine painting the outline of your hand on paper. That outline is a contour. Now you can measure: how large is the area? how long is the perimeter? how round vs spiky is it? OpenCV contours are lists of boundary points, and from them you can compute a full mathematical "fingerprint" of any shape — area, perimeter, convexity, orientation, aspect ratio.
// Contour Descriptors
Area (shoelace formula): A = ½|Σᵢ(xᵢ·yᵢ₊₁ - xᵢ₊₁·yᵢ)| Circularity (1.0 = perfect circle): C = 4π·Area / Perimeter² Aspect Ratio (bounding box): AR = width / height Extent (object fills how much of its bounding box): E = Area / (bounding_box_width × height) Solidity (convex hull fill ratio): S = Area / Convex_Hull_Area
Hu Moments: 7 invariant values derived from image moments.
Invariant to scale, translation, and rotation — unique shape fingerprint.
mu(p,q) = Σ Σ (x-x̄)ᵖ(y-ȳ)ᵍ·I(x,y) [central moments]
contours_shape.pypython
import cv2
import numpy as np

img = cv2.imread('shapes.jpg')
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
_, thresh = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)

# Find contours
# RETR_EXTERNAL: only outermost contours
# RETR_TREE: full hierarchy (nested shapes)
# CHAIN_APPROX_SIMPLE: compress horizontal/vertical runs
contours, hierarchy = cv2.findContours(thresh,
    cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

for cnt in contours:
    area = cv2.contourArea(cnt)
    if area < 500: continue  # skip tiny noise

    perimeter = cv2.arcLength(cnt, closed=True)
    circularity = (4 * np.pi * area) / (perimeter**2)

    # Bounding boxes
    x, y, w, h = cv2.boundingRect(cnt)
    rect = cv2.minAreaRect(cnt)   # rotated bounding rect
    (cx,cy), radius = cv2.minEnclosingCircle(cnt)

    # Approximate polygon (reduce vertices)
    # epsilon = 2% of perimeter = tolerance
    epsilon = 0.02 * perimeter
    approx = cv2.approxPolyDP(cnt, epsilon, closed=True)

    # Classify by vertex count
    n = len(approx)
    shape = {3:"triangle", 4:"rectangle",
             5:"pentagon"}.get(n, "circle" if circularity > 0.8 else "polygon")

    # Moments: centre of mass, area, orientation
    M = cv2.moments(cnt)
    cx = int(M['m10'] / M['m00'])  # centroid x
    cy = int(M['m01'] / M['m00'])  # centroid y

    # Hu Moments: rotation/scale/translation invariant
    hu = cv2.HuMoments(M).flatten()
    print(f"{shape}: circularity={circularity:.2f}, hu[0]={hu[0]:.4e}")

    cv2.drawContours(img, [approx], -1, (0,255,0), 2)
    cv2.putText(img, shape, (cx-20,cy), cv2.FONT_HERSHEY_SIMPLEX,
                0.5, (255,255,0), 1)

// Harris Corner Detector — the foundation
Response: R = det(M) - k·trace(M)² M = Σ w(x,y) · [Iₓ² IₓIᵧ ] [IₓIᵧ Iᵧ² ] det(M) = λ₁·λ₂ (product of eigenvalues) trace(M) = λ₁ + λ₂ (sum of eigenvalues) R >> 0 → corner (both λ large) R << 0 → edge (one λ large) |R| ≈ 0 → flat region (both λ small)
k ≈ 0.04–0.06 (empirical constant)
Iₓ, Iᵧ = image gradients (Sobel x and y)
SIFT builds on this: uses Difference-of-Gaussians (DoG) to find keypoints at multiple scales
// SIFT Descriptor (simplified)
For each keypoint: 1. Compute dominant orientation from gradient histogram 2. Rotate neighbourhood to canonical orientation 3. Divide 16×16 region into 4×4 sub-cells 4. Compute 8-bin gradient histogram per sub-cell 5. Concatenate: 4×4×8 = 128-dimensional vector 6. Normalise vector to unit length (lighting invariant)
SIFT: Scale Invariant Feature Transform. Robust to scale, rotation, illumination.
ORB: Oriented FAST + Rotated BRIEF. 100× faster than SIFT, binary descriptor (XOR matching).
Matching distance: Euclidean (SIFT) or Hamming (ORB binary)
keypoint_matching.pypython
import cv2
import numpy as np

img1 = cv2.imread('photo1.jpg', cv2.IMREAD_GRAYSCALE)
img2 = cv2.imread('photo2.jpg', cv2.IMREAD_GRAYSCALE)

# ── ORB (free, fast, good for real-time) ─────────
orb = cv2.ORB_create(nfeatures=500)
kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

# Brute-force matcher with Hamming distance (for binary)
bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)
matches = bf.match(des1, des2)
matches = sorted(matches, key=lambda x: x.distance)

# Draw top 30 matches
result = cv2.drawMatches(img1, kp1, img2, kp2,
                          matches[:30], None,
                          flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS)

# ── SIFT (more accurate, requires opencv-contrib) ─
try:
    sift = cv2.SIFT_create()
    kp1s, des1s = sift.detectAndCompute(img1, None)
    kp2s, des2s = sift.detectAndCompute(img2, None)

    # KNN match + Lowe's ratio test
    bf2 = cv2.BFMatcher(cv2.NORM_L2)
    knn_matches = bf2.knnMatch(des1s, des2s, k=2)

    # Keep only matches where best is <75% of second best
    good = [m for m, n in knn_matches if m.distance < 0.75 * n.distance]
    print(f"Good SIFT matches: {len(good)}")
except:
    print("SIFT needs opencv-contrib-python")

07 · Motion Analysis

Optical Flow

// Tracking how pixels move between video frames

💡 Real Life Analogy
Stand still in a train station and watch people walk. You see each person's direction and speed of movement — a mental "arrow" on everyone. Optical flow computes exactly these arrows for every pixel (dense) or tracked points (sparse) between two consecutive video frames. It's used for: measuring object velocity, action recognition, video stabilisation, and autonomous vehicle speed estimation.
// Brightness Constancy Constraint (core assumption)
I(x, y, t) = I(x + u, y + v, t + 1) Taylor expansion → Optical Flow Equation: Iₓ·u + Iᵧ·v + I_t = 0 where: Iₓ = ∂I/∂x (spatial gradient x) Iᵧ = ∂I/∂y (spatial gradient y) I_t = ∂I/∂t (temporal gradient = frame difference) u,v = optical flow vector at pixel (x,y)
This is ONE equation with TWO unknowns (u,v) — the aperture problem!
Lucas-Kanade: assumes constant flow in a small window → solvable via least squares
Horn-Schunck: global regularisation (smoothness constraint) → dense flow field
Farneback: polynomial approximation of pixel neighbourhood
// Lucas-Kanade Solution
For n pixels in window, stack equations: A·[u,v]ᵀ = -b A = [Iₓ₁ Iᵧ₁] b = [I_t₁] [Iₓ₂ Iᵧ₂] [I_t₂] [ ⋮ ⋮] [ ⋮ ] Least squares: [u,v]ᵀ = (AᵀA)⁻¹ · (-Aᵀb) AᵀA = [ΣIₓ² ΣIₓIᵧ] ← this is the Harris M matrix! [ΣIₓIᵧ ΣIᵧ² ]
Good tracking requires AᵀA to be invertible → both eigenvalues large → corners!
This is why Shi-Tomasi "Good Features To Track" uses corner quality = min(λ₁, λ₂)

09 · 3D Reconstruction

Stereo Vision & Depth Maps

// Computing distance from two cameras the way eyes work

💡 Real Life Analogy
Hold a finger in front of your face. Close your left eye — see how its position shifts? Now close the right eye instead. That shift is called disparity, and it encodes depth: close objects have huge disparity, far objects have tiny disparity. Your brain does this calculation instinctively. Stereo vision gives two cameras the same ability: larger disparity = closer object.
// Stereo Depth Formula
Disparity: d = x_L - x_R (pixel difference between cameras) Depth: Z = (f · B) / d where: f = focal length (pixels) B = baseline (distance between cameras in metres) d = disparity (pixels) — must be > 0 Point cloud (3D coords): X = Z · (u - cx) / fx Y = Z · (v - cy) / fy Z = (f · B) / d
Epipolar geometry: corresponding points lie on conjugate horizontal lines.
Rectification: stereo pair transformed so epipolar lines are perfectly horizontal.
Stereo matching (SGBM, BM): for each pixel in left image, find matching pixel in right.
Depth precision: ΔZ ∝ Z²/(f·B) — deeper = less precise.

Line Detection, Shape Fitting & Geometric Primitives

Finding lines, circles, ellipses, and arbitrary polygons in images. The Hough family transforms raw edge pixels into geometric parameter votes, while RANSAC robustly fits models to noisy point sets.

╱ Hough Line Transform VOTING
⬡ THINKING PROCESS

The problem: We have edge pixels — how do we know which ones form a line?
Key insight: Any point (x,y) lies on infinitely many lines. In (ρ,θ) parameter space, each point becomes a sinusoidal curve. Points on the same line produce sinusoids that intersect at one (ρ,θ) — that peak = the line.
Why ρ,θ instead of y=mx+b? Vertical lines have m=∞ and break the Cartesian representation.

Line in polar: ρ = x·cos(θ) + y·sin(θ) ρ ∈ [-d, d] d = image diagonal θ ∈ [0°, 180°] For each edge pixel (x,y): for θ in range(0, π, dθ): ρ = x·cos(θ) + y·sin(θ) accumulator[ρ, θ] += 1 ← voting Peak in accumulator = detected line
edges = cv2.Canny(gray, 50, 150) # Standard Hough — returns (ρ, θ) pairs lines = cv2.HoughLines(edges, rho=1, theta=np.pi/180, threshold=100) # Probabilistic — faster, returns endpoints lines = cv2.HoughLinesP(edges, rho=1, theta=np.pi/180, threshold=80, minLineLength=50, maxLineGap=10)
○ Hough Circle Transform 3D SPACE
min radius 20
⬡ THINKING PROCESS

Extension: A circle needs 3 parameters (cx,cy,r) so the accumulator is now a 3D volume.
CHT trick (Gradient method): Each edge pixel's gradient points toward the circle center — cast a vote along that gradient direction. This collapses the 3D problem to a 2D vote per radius.
Cost: O(W·H·R) where R = radius range. Expensive for large radii.

Circle: (x-cx)² + (y-cy)² = r² For each edge pixel (x,y) with gradient angle θ: For r in [rMin, rMax]: cx = x - r·cos(θ) ← gradient direction cy = y - r·sin(θ) accumulator[cx, cy, r] += 1
circles = cv2.HoughCircles(gray, cv2.HOUGH_GRADIENT, dp=1, # accumulator resolution minDist=30, # min distance between centers param1=100, # Canny high threshold param2=30, # accumulator threshold minRadius=10, maxRadius=80)
⦿ RANSAC — Robust Model Fitting ROBUST
⬡ THINKING PROCESS

Problem: Real data has outliers (noise, misdetections). Least-squares is dominated by outliers.
RANSAC insight: Randomly sample the minimum number of points to define a model, count how many other points agree ("inliers"). Repeat. The best model wins.
Key parameter: ε = inlier threshold (distance to model). N = iterations needed: N = log(1-p) / log(1-(1-e)^s) where e = outlier ratio, s = sample size, p = desired confidence.

RANSAC(points, model, ε, N_iter): best_inliers = [] for i in range(N_iter): sample = random_sample(points, min_sample) model = fit(sample) ← minimal fit inliers = [p for p in points if dist(p, model) < ε] if len(inliers) > len(best_inliers): best_inliers = inliers return refit(best_inliers) ← final fit
⬟ Shape Fitting — Poly, Ellipse, Hull GEOMETRY
⬡ THINKING PROCESS

approxPolyDP uses Ramer-Douglas-Peucker: finds the point farthest from the line segment between endpoints. If > ε, it's kept as a vertex. Recurse on both halves. Result: a polygon that stays within ε pixels of the original contour.

RDP algorithm: O(n log n) average ε controls approximation tightness: Small ε → many vertices (close to contour) Large ε → few vertices (rough polygon) cv2.approxPolyDP(contour, epsilon, closed=True)

Perspective Transform & Homography

Mapping between planes in 3D. The homography matrix H encodes the full projective transformation between two views of a planar surface. Essential for document scanning, AR, panorama stitching, and lane detection.

⟁ Homography — 4-Point Perspective Warp 8 DOF
⬡ THINKING PROCESS

Document scanning: A flat document viewed at an angle looks like a trapezoid. We know it should be a rectangle. Pick 4 corner correspondences and solve for H. This is a 2D projective transform that un-does the camera angle.

Homography maps: x' = H·x (homogeneous coords) [x'] [h1 h2 h3][x] [y'] = [h4 h5 h6][y] then divide by w' [w'] [h7 h8 1][1] H has 8 DOF (9 params, scale-invariant) Requires minimum 4 point correspondences. Each correspondence gives 2 linear equations → 8 unknowns. Solved via DLT (Direct Linear Transform) + SVD.
# 4 source points (corners of document) src_pts = np.float32([[120,80],[420,60], [460,380],[80,400]]) dst_pts = np.float32([[0,0],[400,0], [400,480],[0,480]]) H, _ = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0) warped = cv2.warpPerspective(img, H, (400, 480))
⊞ DLT — Solving for H MATH CORE
⬡ THINKING PROCESS

Each point pair (x↔x') gives us 2 equations: Cross-product formulation x'×(Hx)=0 expands to a row of a matrix A. Stack 4 pairs → 8×9 matrix. SVD: The solution is the right singular vector corresponding to the smallest singular value. This minimizes ||Ah||² subject to ||h||=1.

For each correspondence (xi, xi'): [-xi 0 xi·xi'] ← row from cross-product [0 -xi yi·xi'] Stack 4 pairs → matrix A (8×9) Solve: min ||Ah|| s.t. ||h||=1 Solution: h = last column of V in SVD(A)
⊹ Affine vs Projective vs Euclidean HIERARCHY
Euclidean (3 DOF): rotation + translation Preserves: distances, angles Similarity (4 DOF): + uniform scale Preserves: angles, ratios Affine (6 DOF): + shear + non-uniform scale Preserves: parallelism, ratios Projective (8 DOF): full planar mapping Preserves: incidence only
⬡ THINKING PROCESS

Each step up the hierarchy adds DOF and loses invariants. Robot navigation: use Euclidean (rigid body). Document scan: use Projective. Panorama: use Homography between image planes.

Radial distortion (dominant): r² = x² + y² x' = x(1 + k1·r² + k2·r⁴ + k3·r⁶) y' = y(1 + k1·r² + k2·r⁴ + k3·r⁶) Tangential (off-center lens): x' += 2p1·xy + p2(r²+2x²) y' += p1(r²+2y²) + 2p2·xy dist = [k1, k2, p1, p2, k3]

⬡ THINKING PROCESS

Why sub-pixel corners? 1px error in corner = ~0.5° error in angle measurements. cornerSubPix refines to ~0.1px.

Stereo Vision & Depth Estimation

Two calibrated cameras enable triangulation to recover metric 3D structure. The disparity map encodes depth. Fundamental for robot perception, autonomous vehicles, and 3D reconstruction.

⇆ Stereo Geometry — Epipolar Constraint TRIANGULATION
⬡ THINKING PROCESS

Core insight: A point in the left image maps to a line (epipolar line) in the right image, not a full 2D search. This reduces correspondence matching from O(W×H) to O(W) per pixel.
After rectification: Epipolar lines become horizontal. Matching reduces to 1D search. Disparity d = xL - xR. Depth Z = f·B/d where B = baseline, f = focal length.

Epipolar: xR · F · xL = 0 F = K_R^-T · [t]× · R · K_L^-1 (Fundamental) E = [t]× · R (Essential, calibrated) Depth from disparity: Z = (f · B) / d d = xL - xR (disparity in pixels) B = baseline distance (meters) f = focal length (pixels)
# Rectify stereo pair R1,R2,P1,P2,Q = cv2.stereoRectify(K1,d1,K2,d2, imgSize, R, T)[:5] # Compute disparity stereo = cv2.StereoSGBM_create( minDisparity=0, numDisparities=128, blockSize=11, P1=8*3*11**2, P2=32*3*11**2) disp = stereo.compute(imgL, imgR) # Reproject to 3D: Q is 4×4 disparity-to-depth pts3D = cv2.reprojectImageTo3D(disp, Q)
≋ SGBM — Semi-Global Block Matching DISPARITY
⬡ THINKING PROCESS

Block matching alone: fast but noisy (ambiguous in textureless regions).
SGBM insight: Add smoothness constraint via dynamic programming along 8 directions. Cost function: C(p,d) = match_cost(p,d) + P1·|Δd=1| + P2·|Δd>1|. P1 penalizes small disparity changes, P2 penalizes large jumps (occlusions).

Cost(p, d) = SAD(left_patch, right_patch_at_d) Path cost: L_r(p,d) = C(p,d) + min( L_r(p-r, d), L_r(p-r, d±1) + P1, min_k L_r(p-r, k) + P2) Aggregate over 8 directions (semi-global) Choose d* = argmin_d Σ_r L_r(p,d)
△ Triangulation & Point Cloud 3D MATH
Given camera matrices P1, P2 and matches x1, x2: AX = 0 where A is 4×4: [x1 × P1] (2 rows from cross-product) [x2 × P2] (2 rows) X = last column of V in SVD(A) Dehomogenize: X3D = X[:3] / X[3] cv2.triangulatePoints(P1, P2, pts1, pts2)
⬡ THINKING PROCESS

Two rays from two camera centers should intersect in 3D. In practice they don't (noise). DLT finds the point that minimizes reprojection error simultaneously in both views. The disparity-to-depth map Q handles this for dense stereo.

Object Tracking Algorithms

Tracking maintains identity of objects across frames. Different algorithms trade-off between speed, accuracy, and robustness to occlusion and appearance change.

⊙ Kalman Filter — State Estimation PREDICT+UPDATE
⬡ THINKING PROCESS

Two-step Bayesian filter: Predict where the object will be using a motion model. Update using the noisy measurement. The Kalman gain K balances how much to trust the prediction vs. measurement — based on their respective uncertainties.
State for tracking: [x, y, vx, vy] — position + velocity. Measurement: just [x, y].

State: x = [px, py, vx, vy]ᵀ Predict: x̂ = F·x + B·u ← motion model P̂ = F·P·Fᵀ + Q ← covariance grows Update: K = P̂·Hᵀ·(H·P̂·Hᵀ+R)⁻¹ ← Kalman gain x = x̂ + K·(z - H·x̂) ← fuse measurement P = (I - K·H)·P̂ ← covariance shrinks Q = process noise R = measurement noise

Analogy: Treat gradient magnitude as elevation. Flood from user-placed markers (seeds). Where different floods meet = watershed boundary = object boundary.

Pose Estimation — PnP & solvePnP

Given known 3D points and their 2D projections, recover the camera's position and orientation (6-DOF pose). Critical for AR, robot grasping, and visual servoing.

⟳ PnP — Perspective-n-Point Problem 6-DOF POSE
⬡ THINKING PROCESS

P3P: Minimum case — 3 points give up to 4 solutions. EPnP (Efficient PnP): Expresses all world points as weighted sum of 4 virtual control points. Converts to linear system, solves with SVD. O(n) — best for large n.
Rodrigues rotation: cv2 uses rotation vector r where |r| = angle and r/|r| = axis. Compact 3D representation. cv2.Rodrigues(rvec) converts to 3×3 rotation matrix.
RANSAC+PnP: For feature matching where many correspondences are wrong — iterate PnP on random subsets, pick best inlier set.

Minimize reprojection error: Σ ||x_i - π(K, R, t, X_i)||² x_i = observed 2D X_i = known 3D π(.) = projection function: x' = K · [R|t] · X u = fx·(R·X+t)_x / (R·X+t)_z + cx Rodrigues: R = I + sin(θ)·K̂ + (1-cos(θ))·K̂² where K̂ = skew(r/|r|), θ = |r|

Visual SLAM — Simultaneous Localization & Mapping

A robot must build a map of an unknown environment while simultaneously figuring out where it is in that map. Visual SLAM uses cameras as the primary sensor.

⟳ Visual SLAM Pipeline — Full Architecture SYSTEM
⬡ THINKING PROCESS

Front-end (Tracking): Per-frame. Detect/match features → estimate camera motion with PnP or Essential Matrix. Fast, local, may drift.
Back-end (Optimization): Bundle adjustment minimizes reprojection error over all keyframes simultaneously. This is the expensive part — solved with Levenberg-Marquardt over a sparse graph.
Loop Closure: Recognize a previously visited place (using BoW vocabulary tree). Add constraint to graph → correct accumulated drift globally.
Key insight: Without loop closure, error accumulates proportional to distance traveled. Loop closure constrains the entire trajectory at once.

Bundle Adjustment (core optimization): min Σ_i Σ_j ρ(||x_ij - π(K,R_i,t_i,X_j)||²) R,t,X x_ij = observed 2D keypoint j in frame i π(.) = projection function X_j = 3D landmark position ρ(.) = robust loss (Huber) against outliers Solved with: Sparse Levenberg-Marquardt Graph: Poses + Landmarks as nodes Observations as edges (factor graph)
Bag-of-Words (Loop Detection): Visual vocabulary: cluster descriptors into K visual words (K-Means tree) Each image = histogram over visual words bow_vec[word_id] += tf-idf weight Similarity score: DBoW2 score(q, db) If score > threshold → loop candidate Verify with geometric check (PnP) Key libraries: g2o / GTSAM → factor graph optimization DBoW2 → place recognition ORB-SLAM3 → complete system
⬡ ICP — Iterative Closest Point POINT CLOUD
⬡ THINKING PROCESS

Problem: Align two 3D point clouds (e.g., LiDAR scan to map). No known correspondences.
ICP bootstrap: Associate nearest neighbors → compute optimal rigid transform (SVD on covariance) → apply → repeat. Converges to local minimum — needs good initial guess.
Optimal transform from SVD: H = Σ (pi - p̄)(qi - q̄)ᵀ → SVD(H) = UΣVᵀ → R = VUᵀ.

ICP(source_pts P, target_pts Q): while not converged: 1. For each p in P, find nearest q in Q 2. Compute centroids p̄, q̄ 3. H = Σ (p_i-p̄)(q_i-q̄)ᵀ ← covariance 4. U,Σ,Vᵀ = SVD(H) 5. R = V·Uᵀ t = q̄ - R·p̄ 6. Apply: P = R·P + t 7. Check: if ||Δt||<ε: break
