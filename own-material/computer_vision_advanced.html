01 · Colour Spaces

Colour Space Transformations

// Why RGB is not always the right way to represent colour

💡 Real Life Analogy
RGB is like describing a person by their exact bone structure — precise but fragile. Change the lighting and all three numbers change drastically, even though the person looks the same. HSV is like describing them as "tall, wearing a red jacket, standing in shadows" — hue (colour identity) stays the same even when brightness changes. This is why HSV is used for colour-based object tracking.

Different tasks need different colour spaces. RGB mixes colour and brightness. HSV/HSL separates them. LAB mimics human perception. YCrCb is used in video/compression (separates luma from chroma).

// RGB → HSV conversion
Let R,G,B ∈ [0,1] V = max(R,G,B) S = (V - min(R,G,B)) / V (if V ≠ 0) H = 60 × (G - B)/(V - min) if V = R H = 60 × (B - R)/(V - min) + 120 if V = G H = 60 × (R - G)/(V - min) + 240 if V = B H = H + 360 if H < 0
H = Hue [0°–360°] — the colour wheel angle
S = Saturation [0–1] — how "vivid" vs grey
V = Value [0–1] — brightness
OpenCV stores H/2 (0–180), S×255, V×255 in uint8
// RGB → CIE LAB (perceptually uniform)
Step 1: RGB → XYZ (via linear transform + gamma) Step 2: XYZ normalised by D65 white point (Xn,Yn,Zn) Step 3: f(t) = t^(1/3) if t > 0.008856 f(t) = 7.787t + 16/116 otherwise L* = 116·f(Y/Yn) - 16 (lightness, 0–100) a* = 500·(f(X/Xn) - f(Y/Yn)) (green↔red axis) b* = 200·(f(Y/Yn) - f(Z/Zn)) (blue↔yellow axis)
LAB: equal Euclidean distances = equal perceived colour differences.
Perceptual colour distance: ΔE = √(ΔL² + Δa² + Δb²)
Very useful for comparing colours the way humans see them.

import cv2
import numpy as np

img = cv2.imread('image.jpg')

# ── Conversions ──────────────────────────────
hsv   = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

hls   = cv2.cvtColor(img, cv2.COLOR_BGR2HLS)

# ── HSV colour masking (track orange object) ──
# OpenCV H range = 0-180, S/V = 0-255
lower_orange = np.array([10, 100, 100])
upper_orange = np.array([25, 255, 255])
mask = cv2.inRange(hsv, lower_orange, upper_orange)
result = cv2.bitwise_and(img, img, mask=mask)

# ── Skin detection in YCrCb ──────────────────
# Skin tone falls in narrow Cr/Cb range regardless of brightness
lower_skin = np.array([0,  133, 77], dtype=np.uint8)
upper_skin = np.array([255, 173, 127], dtype=np.uint8)

colour1 = np.array([[[255, 100, 50]]], dtype=np.uint8)
colour2 = np.array([[[240, 110, 60]]], dtype=np.uint8)
lab1 = cv2.cvtColor(colour1, cv2.COLOR_BGR2LAB)[0,0].astype(float)
lab2 = cv2.cvtColor(colour2, cv2.COLOR_BGR2LAB)[0,0].astype(float)
delta_e = np.sqrt(np.sum((lab1 - lab2)**2))
print(f"ΔE perceptual distance: {delta_e:.2f}")
02 · Frequency Domain

Fourier Transform

// Decomposing images into sine waves

💡 Real Life Analogy
A song is just air pressure over time. But you can view it as a spectrum in a music equaliser — seeing which frequencies are loud (bass, treble). The Fourier Transform does the same for images: it shows which spatial frequencies are present. Low frequencies = gradual brightness changes (backgrounds). High frequencies = sharp edges, fine texture, noise. You can then filter frequencies before converting back — like tweaking the EQ.
// 2D Discrete Fourier Transform (DFT)
F(u, v) = Σₓ Σᵧ f(x,y) · e^(-j2π(ux/M + vy/N)) Power Spectrum: |F(u,v)|² = Re(F)² + Im(F)² Inverse DFT (reconstruct image): f(x,y) = (1/MN) Σᵤ Σᵥ F(u,v) · e^(j2π(ux/M + vy/N))
u,v = frequency coordinates  |  x,y = spatial coordinates
M,N = image dimensions  |  j = √(-1) (imaginary unit)
Centre of spectrum = DC component (average brightness) = lowest freq
Corners = highest spatial frequencies (fine detail, noise)
🔇

Low-pass filter

Keep only low-frequency components (small circle in centre of spectrum). Result: blurred image. Removes noise and fine detail. Equivalent to Gaussian blur.

🔔

High-pass filter

Remove low frequencies, keep high. Result: edges and textures highlighted, background removed. Used for sharpening and texture analysis.

🎚️

Band-pass filter

Keep only a ring of frequencies. Useful for finding periodic patterns, removing specific noise (e.g. moire patterns from scanned images).

fourier_filtering.pypython
import cv2
import numpy as np

img = cv2.imread('image.jpg', cv2.IMREAD_GRAYSCALE)

# ── Forward DFT ──────────────────────────────────
dft = np.fft.fft2(img)                  # complex 2D array
dft_shifted = np.fft.fftshift(dft)     # move DC to centre

# Visualise as log magnitude spectrum
magnitude = np.abs(dft_shifted)
log_spectrum = 20 * np.log10(magnitude + 1)
spectrum_vis = cv2.normalize(log_spectrum, None, 0, 255,
                               cv2.NORM_MINMAX, cv2.CV_8U)

# ── Low-pass filter (blur in frequency domain) ───
rows, cols = img.shape
crow, ccol = rows // 2, cols // 2
radius = 30  # pixels — larger = less blur

mask = np.zeros((rows, cols), np.uint8)
cv2.circle(mask, (ccol, crow), radius, 1, -1)  # circular window

# Apply mask → inverse DFT → reconstruct image
filtered_dft = dft_shifted * mask
idft_shifted  = np.fft.ifftshift(filtered_dft)
img_back = np.abs(np.fft.ifft2(idft_shifted))
img_back = np.uint8(np.clip(img_back, 0, 255))

# ── High-pass filter ──────────────────────────────
hp_mask = 1 - mask   # invert: keep edges not centre
hp_fft = dft_shifted * hp_mask
hp_back = np.abs(np.fft.ifft2(np.fft.ifftshift(hp_fft)))
hp_back = cv2.normalize(hp_back, None, 0, 255, cv2.NORM_MINMAX, cv2.CV_8U)

# OpenCV also has dft: slightly faster for large images
dft_cv = cv2.dft(np.float32(img), flags=cv2.DFT_COMPLEX_OUTPUT)
03 · Shape Detection

Hough Transform

// Detecting lines, circles, and arbitrary shapes by voting

💡 Real Life Analogy
You have many dots on a piece of paper and want to find which line passes through the most dots. Instead of testing every possible line, the Hough Transform inverts the problem: each dot votes for all possible lines it could be on. Lines that get the most votes probably exist. It's like an election — if many people independently "vote" for the same candidate, that candidate is real.
// Hough Line Transform — Normal form
ρ = x·cos(θ) + y·sin(θ) ρ = perpendicular distance from origin to line θ = angle of the perpendicular (0° to 180°) For each edge pixel (x,y): for each θ in [0°, 180°]: ρ = x·cos(θ) + y·sin(θ) accumulator[ρ][θ] += 1 ← VOTE! Peak in accumulator = detected line
(ρ,θ) = Hough parameter space (accumulator array)
Traditional (y=mx+b) fails for vertical lines (m=∞). Normal form avoids this.
Probabilistic Hough (HoughLinesP) is faster — samples random edge subsets.
// Hough Circle Transform
Circle: (x - a)² + (y - b)² = r² For each edge pixel (x,y) and each radius r: for each angle θ in [0°, 360°]: a = x - r·cos(θ) b = y - r·sin(θ) accumulator[a][b][r] += 1 Peak at (a,b,r) = circle centre at (a,b) with radius r
Computationally heavy (3D accumulator). OpenCV uses gradient-based method (faster).
param1 = Canny high threshold used internally
param2 = accumulator threshold (higher = fewer, more certain circles)
hough_detection.pypython
import cv2
import numpy as np

img   = cv2.imread('image.jpg')
gray  = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
edges = cv2.Canny(gray, 50, 150)

# ── Line detection (probabilistic Hough) ─────────
# rho=1px resolution, theta=1° resolution
# threshold=100: minimum votes to be a line
# minLineLength=50: discard lines shorter than 50px
# maxLineGap=10: max gap to connect into one line
lines = cv2.HoughLinesP(edges,
    rho=1, theta=np.pi/180,
    threshold=100, minLineLength=50, maxLineGap=10)

if lines is not None:
    for line in lines:
        x1, y1, x2, y2 = line[0]
        cv2.line(img, (x1,y1), (x2,y2), (0,255,0), 2)

# ── Circle detection ──────────────────────────────
# Uses gradient information, not raw edge image
# dp=1: accumulator resolution = image resolution
# minDist=30: min distance between circle centres
# param1=50: Canny high threshold
# param2=30: accumulator threshold (lower = more circles)
# minRadius/maxRadius: constrain circle size
circles = cv2.HoughCircles(gray,
    cv2.HOUGH_GRADIENT, dp=1, minDist=30,
    param1=50, param2=30,
    minRadius=10, maxRadius=100)

if circles is not None:
    circles = np.round(circles[0]).astype(int)
    for (cx, cy, r) in circles:
        cv2.circle(img, (cx, cy), r, (0,255,0), 2)
        cv2.circle(img, (cx, cy), 2, (0,0,255), 3)  # centre
04 · Shape Analysis

Contours & Shape Descriptors

// Finding, measuring and classifying shapes mathematically

💡 Real Life Analogy
Imagine painting the outline of your hand on paper. That outline is a contour. Now you can measure: how large is the area? how long is the perimeter? how round vs spiky is it? OpenCV contours are lists of boundary points, and from them you can compute a full mathematical "fingerprint" of any shape — area, perimeter, convexity, orientation, aspect ratio.
// Contour Descriptors
Area (shoelace formula): A = ½|Σᵢ(xᵢ·yᵢ₊₁ - xᵢ₊₁·yᵢ)| Circularity (1.0 = perfect circle): C = 4π·Area / Perimeter² Aspect Ratio (bounding box): AR = width / height Extent (object fills how much of its bounding box): E = Area / (bounding_box_width × height) Solidity (convex hull fill ratio): S = Area / Convex_Hull_Area
Hu Moments: 7 invariant values derived from image moments.
Invariant to scale, translation, and rotation — unique shape fingerprint.
mu(p,q) = Σ Σ (x-x̄)ᵖ(y-ȳ)ᵍ·I(x,y) [central moments]
contours_shape.pypython
import cv2
import numpy as np

img = cv2.imread('shapes.jpg')
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
_, thresh = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)

# Find contours
# RETR_EXTERNAL: only outermost contours
# RETR_TREE: full hierarchy (nested shapes)
# CHAIN_APPROX_SIMPLE: compress horizontal/vertical runs
contours, hierarchy = cv2.findContours(thresh,
    cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

for cnt in contours:
    area = cv2.contourArea(cnt)
    if area < 500: continue  # skip tiny noise

    perimeter = cv2.arcLength(cnt, closed=True)
    circularity = (4 * np.pi * area) / (perimeter**2)

    # Bounding boxes
    x, y, w, h = cv2.boundingRect(cnt)
    rect = cv2.minAreaRect(cnt)   # rotated bounding rect
    (cx,cy), radius = cv2.minEnclosingCircle(cnt)

    # Approximate polygon (reduce vertices)
    # epsilon = 2% of perimeter = tolerance
    epsilon = 0.02 * perimeter
    approx = cv2.approxPolyDP(cnt, epsilon, closed=True)

    # Classify by vertex count
    n = len(approx)
    shape = {3:"triangle", 4:"rectangle",
             5:"pentagon"}.get(n, "circle" if circularity > 0.8 else "polygon")

    # Moments: centre of mass, area, orientation
    M = cv2.moments(cnt)
    cx = int(M['m10'] / M['m00'])  # centroid x
    cy = int(M['m01'] / M['m00'])  # centroid y

    # Hu Moments: rotation/scale/translation invariant
    hu = cv2.HuMoments(M).flatten()
    print(f"{shape}: circularity={circularity:.2f}, hu[0]={hu[0]:.4e}")

    cv2.drawContours(img, [approx], -1, (0,255,0), 2)
    cv2.putText(img, shape, (cx-20,cy), cv2.FONT_HERSHEY_SIMPLEX,
                0.5, (255,255,0), 1)
05 · Feature Detection

Keypoints, SIFT & ORB

// Finding and matching distinctive points across images

💡 Real Life Analogy
When you look at a photo of a cathedral and try to recognise it in another photo (rotated, zoomed, partial), you instinctively look for distinctive landmarks — the pointed tower tip, the rose window, the arched doorway. Keypoint detectors find the visual equivalent: corners, blobs, and unique texture patches that are recognisable from many angles and scales. Each keypoint gets a descriptor vector — a numeric fingerprint — used for matching.
detect
Keypoint Detection

Find stable, distinctive points (corners, blobs)

describe
Descriptor Extraction

Compute 128-D (SIFT) or 256-bit (ORB) vector per point

match
Descriptor Matching

Find nearest neighbours in descriptor space

filter
RANSAC / Ratio Test

Remove outliers, keep reliable matches

estimate
Homography

Compute geometric transform between images

// Harris Corner Detector — the foundation
Response: R = det(M) - k·trace(M)² M = Σ w(x,y) · [Iₓ² IₓIᵧ ] [IₓIᵧ Iᵧ² ] det(M) = λ₁·λ₂ (product of eigenvalues) trace(M) = λ₁ + λ₂ (sum of eigenvalues) R >> 0 → corner (both λ large) R << 0 → edge (one λ large) |R| ≈ 0 → flat region (both λ small)
k ≈ 0.04–0.06 (empirical constant)
Iₓ, Iᵧ = image gradients (Sobel x and y)
SIFT builds on this: uses Difference-of-Gaussians (DoG) to find keypoints at multiple scales
// SIFT Descriptor (simplified)
For each keypoint: 1. Compute dominant orientation from gradient histogram 2. Rotate neighbourhood to canonical orientation 3. Divide 16×16 region into 4×4 sub-cells 4. Compute 8-bin gradient histogram per sub-cell 5. Concatenate: 4×4×8 = 128-dimensional vector 6. Normalise vector to unit length (lighting invariant)
SIFT: Scale Invariant Feature Transform. Robust to scale, rotation, illumination.
ORB: Oriented FAST + Rotated BRIEF. 100× faster than SIFT, binary descriptor (XOR matching).
Matching distance: Euclidean (SIFT) or Hamming (ORB binary)
keypoint_matching.pypython
import cv2
import numpy as np

img1 = cv2.imread('photo1.jpg', cv2.IMREAD_GRAYSCALE)
img2 = cv2.imread('photo2.jpg', cv2.IMREAD_GRAYSCALE)

# ── ORB (free, fast, good for real-time) ─────────
orb = cv2.ORB_create(nfeatures=500)
kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

# Brute-force matcher with Hamming distance (for binary)
bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)
matches = bf.match(des1, des2)
matches = sorted(matches, key=lambda x: x.distance)

# Draw top 30 matches
result = cv2.drawMatches(img1, kp1, img2, kp2,
                          matches[:30], None,
                          flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS)

# ── SIFT (more accurate, requires opencv-contrib) ─
try:
    sift = cv2.SIFT_create()
    kp1s, des1s = sift.detectAndCompute(img1, None)
    kp2s, des2s = sift.detectAndCompute(img2, None)

    # KNN match + Lowe's ratio test
    bf2 = cv2.BFMatcher(cv2.NORM_L2)
    knn_matches = bf2.knnMatch(des1s, des2s, k=2)

    # Keep only matches where best is <75% of second best
    good = [m for m, n in knn_matches if m.distance < 0.75 * n.distance]
    print(f"Good SIFT matches: {len(good)}")
except:
    print("SIFT needs opencv-contrib-python")
06 · Geometric Transforms

Homography & Perspective

// Mapping one plane to another: panoramas, AR, document scanning

💡 Real Life Analogy
When you photograph a whiteboard at an angle, it looks like a parallelogram. Homography unwarps that back to a flat rectangle — as if you were looking directly above it. This same math powers: panorama stitching (aligning multiple photos), AR marker tracking (placing virtual objects on real surfaces), document scanning (straightening scanned paper).
// Homography Matrix (3×3)
Homogeneous coordinates: p' = H · p [x'w] [h11 h12 h13] [x] [y'w] = [h21 h22 h23] × [y] [w ] [h31 h32 1 ] [1] Final: x' = x'w / w y' = y'w / w H has 8 degrees of freedom (last element = 1 by convention) Needs minimum 4 point correspondences to solve. Solved via DLT (Direct Linear Transform): Ah = 0 → SVD of A → h = last column of V
Affine transform: 6 DoF (no perspective, parallel lines stay parallel)
Homography: 8 DoF (full perspective, parallel lines can converge)
RANSAC: randomly sample 4 points, compute H, count inliers, repeat
After N iterations: keep H with most inliers = robust to outlier matches

import cv2
import numpy as np

img = cv2.imread('document.jpg')

# ── Manual: 4 corners clicked by user ─────────────
# src = corners in the distorted image
# dst = desired output positions (rectangle)
src_pts = np.float32([[120,80], [580,50],
                        [620,480], [80,500]])
dst_pts = np.float32([[0,0],   [500,0],
                        [500,600],[0,600]])

H, _ = cv2.findHomography(src_pts, dst_pts)
warped = cv2.warpPerspective(img, H, (500, 600))

# ── From keypoint matches (RANSAC) ────────────────
# Assuming 'good' matches from SIFT/ORB above
if len(good) > 4:
    src_pts = np.float32(
        [kp1s[m.queryIdx].pt for m in good]).reshape(-1,1,2)
    dst_pts = np.float32(
        [kp2s[m.trainIdx].pt for m in good]).reshape(-1,1,2)

    print(f"Inlier matches: {len(inliers)} / {len(good)}")
07 · Motion Analysis

Optical Flow

// Tracking how pixels move between video frames

💡 Real Life Analogy
Stand still in a train station and watch people walk. You see each person's direction and speed of movement — a mental "arrow" on everyone. Optical flow computes exactly these arrows for every pixel (dense) or tracked points (sparse) between two consecutive video frames. It's used for: measuring object velocity, action recognition, video stabilisation, and autonomous vehicle speed estimation.
// Brightness Constancy Constraint (core assumption)
I(x, y, t) = I(x + u, y + v, t + 1) Taylor expansion → Optical Flow Equation: Iₓ·u + Iᵧ·v + I_t = 0 where: Iₓ = ∂I/∂x (spatial gradient x) Iᵧ = ∂I/∂y (spatial gradient y) I_t = ∂I/∂t (temporal gradient = frame difference) u,v = optical flow vector at pixel (x,y)
This is ONE equation with TWO unknowns (u,v) — the aperture problem!
Lucas-Kanade: assumes constant flow in a small window → solvable via least squares
Horn-Schunck: global regularisation (smoothness constraint) → dense flow field
Farneback: polynomial approximation of pixel neighbourhood
// Lucas-Kanade Solution
For n pixels in window, stack equations: A·[u,v]ᵀ = -b A = [Iₓ₁ Iᵧ₁] b = [I_t₁] [Iₓ₂ Iᵧ₂] [I_t₂] [ ⋮ ⋮] [ ⋮ ] Least squares: [u,v]ᵀ = (AᵀA)⁻¹ · (-Aᵀb) AᵀA = [ΣIₓ² ΣIₓIᵧ] ← this is the Harris M matrix! [ΣIₓIᵧ ΣIᵧ² ]
Good tracking requires AᵀA to be invertible → both eigenvalues large → corners!
This is why Shi-Tomasi "Good Features To Track" uses corner quality = min(λ₁, λ₂)
optical_flow.pypython
import cv2
import numpy as np

cap = cv2.VideoCapture('video.mp4')
ret, old_frame = cap.read()
old_gray = cv2.cvtColor(old_frame, cv2.COLOR_BGR2GRAY)

# ── Sparse: Lucas-Kanade on corner points ────────
# Detect good corners to track
p0 = cv2.goodFeaturesToTrack(old_gray, maxCorners=100,
    qualityLevel=0.3, minDistance=7, blockSize=7)

lk_params = dict(winSize=(15,15), maxLevel=3,
    criteria=(cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 10, 0.03))

while True:
    ret, frame = cap.read()
    if not ret: break
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # Calculate flow: returns new positions + status
    p1, st, err = cv2.calcOpticalFlowPyrLK(old_gray, gray, p0, None, **lk_params)

    # Keep only successfully tracked points
    good_new = p1[st == 1]
    good_old = p0[st == 1]

    for (new, old) in zip(good_new, good_old):
        a, b = new.ravel().astype(int)
        c, d = old.ravel().astype(int)
        cv2.arrowedLine(frame, (c,d), (a,b), (0,255,0), 2)

    old_gray = gray.copy()
    p0 = good_new.reshape(-1,1,2)

# ── Dense: Farneback (flow for every pixel) ───────
ret1, f1 = cap.read()
ret2, f2 = cap.read()
g1 = cv2.cvtColor(f1, cv2.COLOR_BGR2GRAY)
g2 = cv2.cvtColor(f2, cv2.COLOR_BGR2GRAY)

flow = cv2.calcOpticalFlowFarneback(g1, g2, None,
    pyr_scale=0.5, levels=3, winsize=15,
    iterations=3, poly_n=5, poly_sigma=1.2, flags=0)

# flow[:,:,0] = u (x-displacement), flow[:,:,1] = v (y-displacement)
magnitude, angle = cv2.cartToPolar(flow[:,:,0], flow[:,:,1])
# Visualise as HSV: hue=direction, saturation=1, value=magnitude
hsv = np.zeros_like(f1)
hsv[...,0] = angle * 90 / np.pi    # 0-180 hue
hsv[...,1] = 255
hsv[...,2] = cv2.normalize(magnitude, None, 0, 255, cv2.NORM_MINMAX)
flow_vis = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)
08 · Camera Models

Camera Intrinsics & Calibration

// The math of how 3D world maps to 2D pixels

💡 Real Life Analogy
A camera is like a pinhole box. Light from a 3D world point passes through the lens (the pinhole) and hits the sensor. The intrinsic matrix K encodes the camera's physics: focal length (how zoomed in), and optical centre (where the image is centred). The extrinsic matrix [R|t] encodes where the camera is in the world — its rotation and translation. Together they explain: "given this 3D point, where exactly does it appear in pixels?"
// Camera Projection Model
3D → 2D pixel projection: λ·[u] [fx 0 cx] [r11 r12 r13 t1] [X] [v] = [0 fy cy] · [r21 r22 r23 t2] · [Y] [1] [0 0 1 ] [r31 r32 r33 t3] [Z] [1] = K · [R | t] · P_world λ = depth (normalise at end) u = fx(X/Z) + cx v = fy(Y/Z) + cy
K = intrinsic matrix (camera-specific, stays constant)
fx, fy = focal length in pixels  |  cx, cy = principal point (image centre)
R = 3×3 rotation matrix  |  t = 3×1 translation vector (extrinsics)
Distortion coefficients k₁,k₂,k₃ (radial) and p₁,p₂ (tangential) model lens warping

objp = np.zeros((7*6, 3), np.float32)
objp[:, :2] = np.mgrid[0:7, 0:6].T.reshape(-1, 2)

objpoints, imgpoints = [], []

for fname in glob.glob('calibration/*.jpg'):
    img = cv2.imread(fname)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    ret, corners = cv2.findChessboardCorners(gray, CHECKERBOARD, None)

    if ret:
        # Refine to sub-pixel accuracy
        corners2 = cv2.cornerSubPix(gray, corners, (11,11), (-1,-1),
            (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001))
        objpoints.append(objp)
        imgpoints.append(corners2)

# Compute K, distortion, rotation/translation per image
ret, K, dist, rvecs, tvecs = cv2.calibrateCamera(
    objpoints, imgpoints, gray.shape[::-1], None, None)

print("Intrinsic matrix K:\n", K)
print("Distortion coefficients:", dist)
print(f"RMS reprojection error: {ret:.4f} px")

# Undistort a new image
new_img = cv2.imread('distorted.jpg')
h, w = new_img.shape[:2]
newK, roi = cv2.getOptimalNewCameraMatrix(K, dist, (w,h), 1, (w,h))
undistorted = cv2.undistort(new_img, K, dist, None, newK)
09 · 3D Reconstruction

Stereo Vision & Depth Maps

// Computing distance from two cameras the way eyes work

💡 Real Life Analogy
Hold a finger in front of your face. Close your left eye — see how its position shifts? Now close the right eye instead. That shift is called disparity, and it encodes depth: close objects have huge disparity, far objects have tiny disparity. Your brain does this calculation instinctively. Stereo vision gives two cameras the same ability: larger disparity = closer object.
// Stereo Depth Formula
Disparity: d = x_L - x_R (pixel difference between cameras) Depth: Z = (f · B) / d where: f = focal length (pixels) B = baseline (distance between cameras in metres) d = disparity (pixels) — must be > 0 Point cloud (3D coords): X = Z · (u - cx) / fx Y = Z · (v - cy) / fy Z = (f · B) / d
Epipolar geometry: corresponding points lie on conjugate horizontal lines.
Rectification: stereo pair transformed so epipolar lines are perfectly horizontal.
Stereo matching (SGBM, BM): for each pixel in left image, find matching pixel in right.
Depth precision: ΔZ ∝ Z²/(f·B) — deeper = less precise.
stereo_depth.pypython
import cv2
import numpy as np

# Assuming calibrated stereo pair (K1, K2, R, T from stereoCalibrate)
imgL = cv2.imread('left.jpg', cv2.IMREAD_GRAYSCALE)
imgR = cv2.imread('right.jpg', cv2.IMREAD_GRAYSCALE)

# ── Stereo rectification ───────────────────────────
# R1, R2 = rotation matrices; P1, P2 = projection matrices
# Q = disparity-to-depth mapping matrix
R1, R2, P1, P2, Q, _, _ = cv2.stereoRectify(
    K1, dist1, K2, dist2, imgL.shape[::-1], R, T)

map1L, map2L = cv2.initUndistortRectifyMap(K1, dist1, R1, P1,
                    imgL.shape[::-1], cv2.CV_16SC2)
map1R, map2R = cv2.initUndistortRectifyMap(K2, dist2, R2, P2,
                    imgR.shape[::-1], cv2.CV_16SC2)

rectL = cv2.remap(imgL, map1L, map2L, cv2.INTER_LINEAR)
rectR = cv2.remap(imgR, map1R, map2R, cv2.INTER_LINEAR)

# ── Compute disparity → depth ──────────────────────
# SGBM = Semi-Global Block Matching (better quality)
stereo = cv2.StereoSGBM_create(
    minDisparity=0, numDisparities=64, blockSize=5,
    P1=8*3*5**2, P2=32*3*5**2, disp12MaxDiff=1,
    mode=cv2.STEREO_SGBM_MODE_SGBM_3WAY)

disparity = stereo.compute(rectL, rectR).astype(np.float32) / 16

# Convert disparity to 3D points
# Q matrix encodes f, cx, cy, baseline
points_3D = cv2.reprojectImageTo3D(disparity, Q)
depth = points_3D[:,:,2]  # Z component = depth in metres


# Visualise disparity as colour map
disp_norm = cv2.normalize(disparity, None, 0, 255, cv2.NORM_MINMAX, cv2.CV_8U)
disp_color = cv2.applyColorMap(disp_norm, cv2.COLORMAP_JET)

CNNs & How Deep Learning Connects

// Why everything above is still inside every neural network

💡 Real Life Analogy
A CNN is a stack of learnable convolution kernels. Where you manually designed a Sobel kernel to detect edges, a CNN learns its own kernels from data. Early layers learn edge detectors (just like Sobel), middle layers learn textures and shapes, deep layers learn semantic concepts ("wheel", "face"). The math is identical — it's just that the kernel values are parameters optimised by gradient descent instead of being hand-crafted.

// CNN Forward Pass Math
Conv layer: O[f,x,y] = Σ_c Σ_i Σ_j I[c, x+i, y+j] · W[f,c,i,j] + b[f] ReLU activation: A = max(0, O) ← kills negative activations Max Pooling (2×2): P[x,y] = max(A[2x:2x+2, 2y:2y+2]) Batch Normalisation: x̂ = (x - μ_B) / √(σ²_B + ε) y = γ·x̂ + β ← learned scale and shift
f = filter index (how many kernels)  |  c = input channel  |  i,j = kernel position
W = learnable weights (= the kernels!)  |  b = bias per filter
Backprop computes ∂Loss/∂W via chain rule → gradient descent updates W
Receptive field grows with depth: deep neurons "see" large image areas

🔗

Classical → Deep Learning Bridge

Conv kernels in CNNs are the same math as filter2D. ReLU is thresholding. Pooling is downsampling. Batch norm is histogram normalisation. Deep learning automates the kernel design.

📐

When to use classical CV

Real-time embedded (no GPU), explainability required, small datasets, geometric problems (calibration, stereo, optical flow), structured environments with known shapes.

🧠

When to use deep learning

Large datasets available, complex unstructured scenes, classification/detection/segmentation, when accuracy matters more than interpretability, cloud/GPU deployment.
